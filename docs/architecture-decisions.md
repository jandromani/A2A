# Architecture decisions and rejected alternatives

**Status:** retrospective ADR summary of the publicly inspectable October 2026 reference architecture. This document is an explanatory record, not a contemporaneous approval trace; approval records and meeting decisions are not published.

## ADR-001 — Bounded task workflow, not unconstrained autonomous execution
**Context:** Enterprise tasks mix read-only information retrieval, tool actions and writes to third-party systems.

**Decision:** Define a small, inspectable workflow state machine with deterministic checks, explicit scopes and separate human approvals before external writes. LangGraph coordinates the implementation. Agent outputs do not bypass the approval gate.

**Alternatives:** Unconstrained LLM tool calling (rejected due to unpredictable external effects), a completely hand-coded single-purpose script (rejected because three distinct cases need shared boundaries).

**Trade-off:** Smaller supported DSL, more explicit coordination overhead, narrower generality. **Evidence:** `app/workflows/engine.py`, `tests/test_governance.py`, `tests/test_platform.py`. Production enforcement requires real identity and policy services.

## ADR-002 — Local testability separated from production identity
**Decision:** Provide local SQLite and simulated connectors to make scenarios reproducible. Production preflight checks for OIDC, Vault, OPA, TLS, database, cache and archive services before deployment is declared ready.

**Alternative:** Claim development Compose credentials and synthetic services are production-ready. Rejected. 

**Trade-off:** A green local build cannot certify production service configuration, restore/recovery or external tenants. **Evidence:** `app/production_preflight.py`, `tests/test_production_activation.py`, `deploy/aws/production/`.

## ADR-003 — Traceability and approvals are first-class data
**Decision:** Store actor, source references, task state, approval requests and usage as separate auditable records. Estimate provider cost from observed usage and configured rates; distinguish estimates from actual invoices. Configure an optional archival path with retention/restore checks.

**Alternative:** Rely exclusively on opaque model logs or prompt transcripts. Rejected due to attribution, privacy and reproducibility concerns.

**Trade-off:** Schema and operational complexity, retention responsibilities and the need to test backup/restore in real cloud accounts. **Evidence:** `app/audit.py`, `app/ledger.py`, `app/usage.py`, `tests/test_audit_archive.py`, `tests/test_restore_verification.py`.

## ADR-004 — Protocol adapters behind scoped contracts
**Decision:** Use official typed MCP tooling where supported, A2A/ANP discovery with explicit coverage boundaries, and Agora connectors with actor-scoped conversation state. Do not claim complete protocol support merely because an endpoint responds.

**Alternative:** A universal protocol abstraction without coverage-specific integration tests. Rejected.

**Trade-off:** Some interoperability is intentionally unsupported until real peer/gateway E2E verification. **Evidence:** `app/sdk_protocols.py`, `app/protocols.py`, `tests/test_protocol_interop.py`.

## Falsifiable review questions
1. Can a user without permissions invoke a write action? Test with local principal fixtures and deny-by-default policies.
2. Does the same workflow resume after a paused approval? Test task checkpoints and idempotency.
3. What happens when the model provider times out? Check recorded fallback and event accounting.
4. Can a second actor read a saved conversation? See actor-scope test.
5. Which gates fail when deploying with missing production credentials? Run production preflight against a dedicated non-production environment.
6. What was personally reviewed by an engineer vs generated by agents? Full provenance is **not published**, and should not be inferred from commits alone.
